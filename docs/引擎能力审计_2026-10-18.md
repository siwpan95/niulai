# 双引擎能力审计（2026-10-18 实测）

> 起因（全哥原话）：「world3d 侧的贴图部分完全没有用到吧？你确定两个引擎的
> 性能得到了完全的发挥？」——实测结论：**没有完全发挥**。本文是逐模块
> 实测账（import 扫描 + 模块 docstring 核对），作为 P5 的事实基础。
> 定位口径（全哥 2026-10-18 拍板）：**本项目仅为验证双引擎所用**——
> 引擎能力覆盖面即验收标准；产物（成片/音频）一律不入仓、不上传 Release。

## 一、实测方法

- `grep -rhoE "from world3d..." niulai/ scripts/ tests/` 扫全部实际 import；
- world3d `engine/` 42 个模块逐个读 docstring 核对职责；
- allin_engine 同法盘点（P4 已盘，本文复核补全）。

## 二、world3d（engine/ 42 模块，实际用 8 个 ≈ 19%）

### 已用（8）

| 模块 | 用途 | 深 |
|------|------|----|
| geometry | MeshData / box 盒体几何 | 全 |
| fonts | CJK 字体解析（字幕） | 全 |
| camera(logic) | look_at_matrix | 单函数 |
| app(platform) | capture 抓帧 | 单函数 |
| oit | WBOIT 透明 | 全（仅 enhanced） |
| postfx | FullscreenQuad + PostChain 的 Bloom/composite | **部分**（SSAO 未接——需 normal/depth MRT） |
| shaders | 只取 `wboit` 一个程序 | **极小**（PBR/皮肤/天空等着色器库全未碰） |
| targets | RenderTarget / bind_texture | 部分（仅 enhanced） |

### 未用（34）——按「验证价值 / 与粗粝美学的兼容」分档

**A 档：贴图与材质子系统（全哥点名，现状 0%）**

| 模块 | 能力 | 验证方式建议 |
|------|------|--------------|
| proctex | 程序化 PBR 纹理（fBm → albedo/metal-rough/normal/emissive，磁盘不存像素） | 地形/水面/角色盒体生成贴图，enhanced profile 渲染对照 |
| material | PBR 材质（金属-粗糙度，对齐 glTF 2.0） | 与 proctex 配套绑定 |
| env | 程序化天空 + IBL 三件套烘焙 | act5 大气系统对接（替换纯色清屏） |
| texproj | 世界→纹理坐标投影（纯数学） | 地形 triplanar 投影 |
| renderer | 完整渲染器（场景→MRT→后处理→屏幕） | enhanced 管线的目标形态 |
| shaders(PBR 部分) | PBR/皮肤/天空等着色器库 | 与 material/proctex 配套 |

**B 档：光照/光学（渲染验证价值高）**

| 模块 | 能力 | 建议 |
|------|------|------|
| csm / soft_shadow | 级联阴影 / PCSS 软阴影 | 盒体角色投影到地形（enhanced） |
| postfx.SSAO | 半分辨率半球核 AO | 需 normal/depth MRT，与 renderer 配套 |
| volumetrics | 高度雾解析积分 + 单次散射 | act1 清晨 / act5 将晓 |
| dof / motionblur | 景深 / 相机重投影运动模糊 | 跃溪/总攻等快镜 |
| framegraph | 声明式帧图（编译期校验） | enhanced 管线复杂化后上 |

**C 档：演出基建（与自研件二选一，验证可平替）**

| 模块 | 能力 | 现状 |
|------|------|------|
| timeline / shot / hud / fixedstep | 关键帧时间轴 / 演出模型 / HUD / 固定步长 | niulai 自研了同类（timeline.py / base.Shot / SubtitleTrack） |
| fsm / orchestration | 确定性 FSM / 事件总线级联 | niulai 用 allin 的 BT/EventBus |
| baked_mesh / greedy_mesh / mesh / mathkit / frustum | 几何工具 | niulai 自研 rig.py 覆盖 |
| scene / scene_build / serialize / perf | 场景图 / JSON 重建 / 热重载 / 性能面板 | 离线渲染未用；perf 可选做 |
| pointcloud + EDL | 点云渲染 | 可做 proof |
| gpu_cull | GPU 剔除 + LOD + indirect draw | 群体戏规模（36 牛）尚不需要 |

**D 档：不适用（离线复刻口径）**

| 模块 | 原因 |
|------|------|
| gltf / skin | 外部模型资产——与「程序化零外部素材」口径冲突；仅作能力 demo 可选 |
| physics / picking | 交互物理 / 鼠标拾取——离线逐帧渲染无交互 |
| adaptive_music / audio | 自适应 BGM / 音频引擎——与 allin 音乐子系统重复，二选一（现用 allin） |

## 四、结论与 P5 提议

**结论：两个引擎均未完全发挥（world3d ≈19%，贴图 0%；allin ≈22%）。**
P4 的「全量增强」表述过强，README 已修正为「首批接入」。

**P5 提议（按验证价值排序，全部 enhanced profile / 显式开启）：**

1. **贴图与材质子系统**（proctex + material + texproj + env + renderer PBR
   管线）——全哥点名的 0% 面：地形/水面/角色程序化 PBR 贴图 + IBL 环境光，
   与 raw 逐帧对照验收；
2. **SSAO + 阴影**（postfx.SSAO + csm/soft_shadow）——normal/depth MRT；
3. **volumetrics 体积雾**（act1 清晨/act5 将晓）；
4. **BrainComponent ECS 挂载**（allin 侧：BT 正式挂实体，闭环「ECS+BT」）；
5. dof/motionblur（快镜）、framegraph（管线收口）、pointcloud（proof）。

D 档（gltf/physics/picking 等）不接入并保持记账口径。
