# 双引擎能力审计（2026-10-18 实测）

> 起因（全哥原话）：「world3d 侧的贴图部分完全没有用到吧？你确定两个引擎的
> 性能得到了完全的发挥？」——实测结论：**没有完全发挥**。本文是逐模块
> 实测账（import 扫描 + 模块 docstring 核对），作为 P5 的事实基础。
> 定位口径（全哥 2026-10-18 拍板）：**本项目仅为验证双引擎所用**——
> 引擎能力覆盖面即验收标准；产物（成片/音频）一律不入仓、不上传 Release。

## 一、实测方法

- `grep -rhoE "from world3d..." niulai/ scripts/ tests/` 扫全部实际 import；
- world3d `engine/` 42 个模块逐个读 docstring 核对职责；
- allin_engine 同法盘点（P4 已盘，本文复核补全）。

## 二、world3d（engine/ 42 模块）

> **覆盖更新（P6 后实测）**：8/42 ≈19% → 24/42 ≈57%（P5）→ **32/42 ≈ 76%（P6）**。
> P6 新增：fsm（act4 阶段时间轴，real）、serialize + scene_build（每幕场景清单
> JSON，real）、perf（帧计时，real）、frustum（群体实例剔除，real）、
> skin / gpu_cull / greedy_mesh / orchestration（proof 对拍）。
> 剩余 10 个未用项**全部有明确理由**（见 §五）。
> 贴图/材质子系统 0% → **全用**（proctex/material/env/texproj/renderer-PBR）。
> 新增接入：renderer、scene、mesh(InstancedMesh)、material、proctex、env、
> texproj、csm、volumetrics、dof、motionblur、framegraph、pointcloud、
> physics、gltf、mathkit（proof）。未用剩 18 个：skin/baked_mesh/greedy_mesh/
> gpu_cull/picking/hud/fixedstep/fsm/orchestration/serialize/scene_build/perf/
> frustum(间接)/adaptive_music/audio（与 allin 二选一）等，逐项理由见下表。

## 四、结论与 P5 落实（2026-10-18 全哥拍板：P5 必须全做）

P5 已落实（本文件 A/B 档全绿 + C 档 proof）：
1. ✅ 贴图材质子系统（proctex/material/env/texproj/renderer PBR）
2. ✅ SSAO + CSM 3 级阴影（soft_shadow.pcss 暴露未接，引擎侧待做）
3. ✅ volumetrics + dof/motionblur
4. ✅ framegraph 管线收口 + pointcloud proof
5. ✅ allin BrainComponent ECS 挂载（BrainRig）+ media CA/physics/gltf proof
6. gpu_cull：评估后不接（规模阈值，记账）

原提议存档：

**结论更新（P5 后）：world3d 24/42 ≈ 57%（贴图/材质/光照/光学全用），
allin ≈ 25%（+BrainComponent ECS 挂载、media CA proof）。P4 的 19%/0% 现状
已成历史；剩余未用项全部有记账理由（不适用/规模阈值/与 allin 二选一）。**

**P5 提议（按验证价值排序，全部 enhanced profile / 显式开启）：**

1. **贴图与材质子系统**（proctex + material + texproj + env + renderer PBR
   管线）——全哥点名的 0% 面：地形/水面/角色程序化 PBR 贴图 + IBL 环境光，
   与 raw 逐帧对照验收；
2. **SSAO + 阴影**（postfx.SSAO + csm/soft_shadow）——normal/depth MRT；
3. **volumetrics 体积雾**（act1 清晨/act5 将晓）；
4. **BrainComponent ECS 挂载**（allin 侧：BT 正式挂实体，闭环「ECS+BT」）；
5. dof/motionblur（快镜）、framegraph（管线收口）、pointcloud（proof）。

D 档（gltf/physics/picking 等）不接入并保持记账口径。


## 五、P6 收尾（剩余 10 个未用项的理由）

P6 的原则：**画面中立且语义等价的才真接入**，其余做 proof 对拍并记账。
每条真接入都用「同帧 md5 对比」证明过画面未变。

### 5.1 本轮真接入（real）

| 模块 | 落点 | 证据 |
|------|------|------|
| fsm | `brains/phases.py`：act4 四阶段（circle/charge/chase/grief）由 `machine_from_keys` 时间轴驱动，替换 4 处散落阈值 | t=0..1320 全扫与旧阈值 **0 失配**；act4 同帧 md5 相同 |
| serialize | `pipeline/scene_manifest.py`：八幕场景结构 + 相机关键帧 -> JSON | 八幕 `output/manifests/*.scene.json`，往返还原一致 |
| scene_build | 同上，`validate()` 实构建校验 mesh 定义 | 八幕 **0 error** |
| perf | `pipeline/render.py`：`FrameStats` 逐帧计时，块日志输出 fps/median/p1/jank | 实测输出 `fps 6.6 (med 13.7 p1 0.4)`（含启动开销） |
| frustum | `pipeline/pbr_frame.py`：群体实例视锥剔除（`intersects_sphere`，半径 4.5） | 6 帧开关 A/B **md5 全同**；但实测**剔除 0 实例**——本片群体戏始终在景内，属"接入但零收益"，记账不吹 |

### 5.2 本轮 proof（对拍，不进成片）

| 模块 | proof 内容 | 证据 |
|------|-----------|------|
| skin | 两骨骼链 `joint_matrices` vs 手算；关节旋转后顶点刚体变换 | tests/test_p6_proofs.py 全过 |
| gpu_cull | `cpu_reference` vs 手算一致、`cpu_lod` 阈值正确；本机 compute 能力探测（GL 4.6 / NVIDIA 617.42 支持） | 同上 |
| greedy_mesh | 4×8 实心块贪心合并 quad 数 <= 逐格，且 <= 10 | 同上 |
| orchestration | `when→then` 级联顺序确定、可重放、环声明被 `RecursionError` 拦截 | 同上 |

### 5.3 仍不接入（10 个，逐条理由）

| 模块 | 理由 |
|------|------|
| soft_shadow | PCSS 需动态 blocker 搜索，接 CSM 是引擎自身未完成的下一步；本工程用固定 PCF 半径 |
| baked_mesh | 与 `cast/rig.shaded_box` 同源同算法（1.00/0.82/0.75/0.50）；替换不改变画面也不增加能力，纯搬运 |
| hud | 离线成片无交互 UI；调试信息走日志（已由 perf 覆盖） |
| picking | 鼠标拾取，离线逐帧渲染无输入设备 |
| fixedstep | 离线按帧号推进，不存在实时 dt 抖动；粒子场内部已固定步长 |
| adaptive_music | 可选依赖 bloodmusic 未安装；BGM 走 allin.audio 的程序化组曲 |
| audio | 与 allin.audio **二选一**，已选 allin（更完整：组曲/拟音/镜头拟音一条龙） |
| app | 应用骨架（窗口+主循环+HUD+基准），niulai 自有离屏渲染循环 |
| shot | 演出模型（导演台底座），niulai 各幕用轻量 `base.Shot` + 相机 lambda，无关键帧插值需求 |
| timeline | glTF 对齐的关键帧插值；niulai 的 `timeline` 是幕表/帧号换算，语义不同 |

**结论**：world3d 32/42 ≈ 76%，剩余 10 项均为「不适用 / 引擎侧未完成 / 与已有实现二选一」。
allin 侧另计（P5 已到 ≈25%，含 ECS+BT 闭环与 media/physics proof）。
