## 二、增强路线图

排序原则：先解除阻塞 → 再补最短板 → 再做锦上添花。

### P3-0　环境自举（阻塞一切，最高优先级）

**现状**：clone 下来跑不动——无 venv、无 ffmpeg、README 路径失效。
**目标**：`bootstrap` 一条命令从零到 `python -m niulai info` 可跑。

- `scripts/bootstrap.py`：探测 Python → 建 `.venv` → `pip install -e .[dev,audio,tts]` →
  探测 ffmpeg（PATH / `NIULAI_FFMPEG` / 常见位置），缺失时**打印下载指引而非静默失败**；
- `scripts/check_env.py`：一次性体检（Python / venv / ffmpeg / 依赖版本 / 磁盘余量），
  输出 PASS/FAIL 表。全片渲染需 ~50GB 临时空间，提前预警；
- README 快速开始改为实际可用路径（去掉已失效的 `E:\Python314`）。

**验收**：干净目录 clone → bootstrap → `info` + `test_smoke` 全绿。

---

### P3-1　多角色配音（最短板，声画性价比最高）

**现状**：`audio/tts.py` 用 SAPI Huihui 单嗓，六幕 36 句全一个声音；
README 已知限制里挂着"SAPI 只有一个中文语音，多角色同嗓"。
对白落位是**硬约束**：每句必须精确落在 `LINES` 的 `t0`，且不能溢出 `t1` 窗口。

**调研结论（2026 现状）**：

| 方案 | 克隆 | 中文 | 时长控制 | 许可 | 本机可行性 |
|------|------|------|----------|------|-----------|
| **IndexTTS-2.5** | 单参考，音色/情感解耦 | 强，拼音纠音 | **0.5–2.0× 时长因子**（正对口型硬约束） | 自定义协议，商用需联系作者 | 需 GPU ✗ |
| **GPT-SoVITS** | 5s 零样本 / 1min 微调 | 中文最强，生态最全 | 靠切句管线 | **MIT，整体可商用** | 需 GPU ✗ |
| CosyVoice 3 | 3s 级，18+ 方言 | 强 | 流式 150ms 首包 | Apache-2.0 | 需 GPU ✗ |
| **edge-tts** | 不支持克隆 | 多个 zh-CN 音色（不同年龄/性别） | 无时长控制 | 在线服务 | **无需 GPU ✓** |

**分两步走**：

- **P3-1a（无卡也能做，立即落地）**：`tts.py` 增加 `VOICE_MAP`——把角色映射到 edge-tts
  的不同 zh-CN 音色（牛妈妈/牛来/云玎/旁白各一嗓），保留 SAPI 作为 `--engine sapi` 回退。
  时长失控问题用**变速不变调**（ffmpeg `atempo`，限制 0.8–1.25× 防机械感）+ 越界告警解决。
- **P3-1b（有卡再做）**：接 IndexTTS-2.5，用时长因子把每句压进 `t0–t1` 窗口——
  这是所有候选里唯一原生支持"指定时长"的，与本工程的数据模型天然契合。

**验收**：新增 `tests/test_voices.py`——断言角色→音色映射唯一、每句落位在窗内、
相邻台词不重叠（现有的字幕时间窗不重叠测试可直接复用为模板）。

---

### P3-2　分块并行渲染（吞吐）

**现状**：单进程 4.9–7.6 fps，全片 154,800 帧 ≈ 5–9 小时；
已有 2 分钟分块策略（防 ffmpeg 静默死亡），但块是**串行**渲的。

**目标**：worker 池并行渲块（每进程一个 pyglet 离屏窗口），N 核 ≈ N× 提速。

- 关键点：**不破坏确定性**——姿态是 `t` 的纯函数 + 固定 seed，块间无状态共享，
  并行结果与串行逐帧 md5 必须一致。这正是现有 `test_determinism` 能兜住的；
- 每块独立 ffmpeg 子进程（沿用现有的 `read1(65536)` 按块排空 stderr，别再用 `for line in`）；
- 块失败只损失 2 分钟，支持 `--resume` 跳过已完成的块（读 manifest）。

**风险**：pyglet 多窗口在 Windows 上需每进程独立创建；先做 2 worker 验证 md5 一致性再放量。

---

### P3-3　OST 去重复

**现状**：三主题 180s 循环 WAV，18 分钟的 act4 会听出重复；README 已挂账。

**两个路线，先做便宜的**：

- **P3-3a 程序化变奏（保确定性，推荐先做）**：给 `audio/ost.py` 的 `MusicPattern` 加
  变奏层——和声转位、配器增删、节奏加密/稀疏、调式临时离调。纯函数 + 固定 seed，
  现有测试体系能直接钉住，零新依赖，零 GPU。
- **P3-3b 生成式（可选）**：ACE-Step（**<4GB VRAM，4GB 卡可跑**）生成分幕主题，
  用它的 repaint / layering 做变奏——这两个模式能把"盲盒抽卡"变成"只重roll 不满意的那段"，
  契合本工程反复迭代的工作流。

**许可证记账（重要）**：

| 模型 | 权重许可 | 商用 |
|------|----------|------|
| ACE-Step | MIT（另有资料标 Apache-2.0，**以官方仓库 LICENSE 为准**） | 允许 |
| YuE2 | 代码 Apache-2.0 / **权重 CC BY-NC 4.0** | **禁** |
| MusicGen | **CC BY-NC 4.0** | **禁** |
| HeartMuLa | Apache-2.0 | 允许 |

本项目定位"不商用"，NC 条款不构成阻塞，但**必须记进 `docs/REFERENCE.md`**——
哪天想商业化，这些是要拆的雷。优先选 ACE-Step。

### P3-4　拟音层（foley 深化）

已有 `audio/foley.py` + CC0 公版录音（风/鸟）。可扩：蹄声、涉水、喘息、狼嚎，
按镜头自动铺（镜头表已有，联络图可导出镜头时间码）。声景从"幕级"下沉到"镜头级"，
是低成本高感知的升级。

## 三、定位层面的一条判断（值得先想清楚）

原片《牛来》的核心叙事卖点是"**全程未使用任何人工智能**、母子二人手搓五年"。
本复刻工程恰恰是程序化 + AI 生成，这个反差本身就是话题点，但也意味着：

**增强方向不应追求"以假乱真"或"修得比原片好看"。**
本工程的价值锚点是另外三个词：**可复现、可审计、可参数化**——
同一个 seed 出同一帧、粗粝感是可调参数而非缺陷、每一处借鉴都记了账。

所以凡是会破坏这三点的增强（比如用视频生成模型直接替换画面、用超分磨掉粗粝感），
一律做成**默认关闭的可选 profile**，并在 README 里如实标注。
这既守住同人学习口径，也让"能修到多好"成为可展示的能力证明。

## 四、建议执行顺序

```
P3-0  环境自举（bootstrap + check_env + README 修路径）   ← 阻塞一切，先做
  ↓
P3-1a 多角色配音 · edge-tts 版（无需 GPU）                ← 最短板，感知最强
  ↓
P3-2  分块并行渲染（先 2 worker 验 md5 一致性）           ← 吞吐，省的是小时
  ↓
P3-3a OST 程序化变奏                                      ← 零依赖零 GPU
  ↓
P3-4  镜头级拟音
  ↓
P4    升采/粗粝度分级/CI/增量渲染（有卡再做 P3-1b、P3-3b）
```
